## Audit coverage limitation (verified)

The existing report said "Pages checked: 1, errors: 0". That is accurate but not meaningful: there was only one page, and the audit script also had gaps that would have hidden problems on a multi-page site:

- It derived page URLs as `<name>.html`, which is wrong for directory-style URLs such as `/about/`.
- It did not check canonical correctness, orphan pages, missing CSS/JS/image files, BreadcrumbList, JSON-LD properties, `og:image` files, sitemap validity or noindex pages in the sitemap.
- It treated an empty `alt=""` the same as a missing one.

## Verified problems

1. Single URL: nothing for Google to choose as a sitelink beyond the homepage.
2. Anchors-only navigation with ambiguous labels ("Packages", "Engagement", "Our Role").
3. All CSS inline: not cacheable or shareable across pages; the stylesheet contained duplicated responsive overrides.
4. Scroll-reveal hid content (`opacity:0`) until JavaScript ran.
5. Small gold kicker text on the light background measured 2.19:1 contrast (WCAG AA needs 4.5:1).
6. No skip link, no visible keyboard focus style on links and buttons, and the nav was a `<div>` rather than a `<nav>`.
7. Footer had no links. The site collects personal information (form, analytics) with no privacy policy.
8. Contact form: no confirmation page or message ever displayed (the success paragraph was permanently `display:none`), no honeypot, no `autocomplete` attributes.
9. Social image was a wide WebP rather than a 1.91:1 JPEG or PNG; some platforms do not render WebP previews.
10. `project.webp` was 440 KB at 1600 px for a card displayed at roughly 630 px.
11. Sitemap carried ignored `changefreq`/`priority` fields.
12. `seo_optimizer.py` hard-coded the homepage title and description (it would overwrite any change) and built sitemap URLs from file paths (`about/index.html`), which would be wrong for directory URLs.
13. The review workflow only staged `index.html`, so it could not propose changes to other pages.
