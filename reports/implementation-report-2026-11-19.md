Decisions:

- **Four service pages, not six.** Planning, grid, land and due diligence each have distinct customer intent and enough approved detail. Market Entry Framework and Development Workstream Management stay on `/services/` (anchors `#market-entry-framework`, `#development-workstream-management`) because their approved descriptions are too short to stand alone without becoming thin or duplicate pages.
- **Not created:** `/services/solar-project-development/` and `/services/bess-development-support/` (no approved technology-specific capability text exists; they would duplicate the homepage and services overview), and `/terms-and-conditions/` (requires legally drafted terms; not invented).
- **No redirects needed.** The only previous URL is `/`, which is unchanged. Old homepage anchors changed (`#services` is now `#starter-packages`; `#approach` content moved to `/about/`).
- The homepage keeps its existing sections (about, six services, ten starter packages, four engagement stages, why Strativa) and now links into the new pages; the contact form moved to `/contact/` and the homepage keeps a contact call to action with `id="contact"`.

## Page-to-keyword map

Maintained in `config/seo_targets.json` under `page_keyword_map`. Summary: homepage owns the broad market terms; `/about/` owns "owner-side development support Australia"; `/services/` owns solar/BESS development and partner terms; each service page owns its own service term; the insight targets the informational question "what is owner-side development support" so it does not compete with `/about/`.

## Sitelink-related work (no outcome can be guaranteed)

Five plainly labelled primary links (Home, About, Services, Insights, Contact) as real `<a>` elements in a `<nav>`; footer links to the four service pages; homepage links to every service page and to Contact; each service page links to related services and Contact; breadcrumbs with BreadcrumbList on all nested pages; unique titles, descriptions and H1s; all pages in the sitemap. Google selects sitelinks algorithmically and usually only after a site has been crawled and has some search demand for the brand.

## Other changes

- Shared `assets/css/site.css` (original CSS carried over, plus new components) and `assets/js/site.js`; no frameworks added.
- Accessibility: skip link, `<nav>` landmarks, `aria-current`, visible focus rings, darker gold for small text on light backgrounds (5.18:1), content visible without JavaScript, reduced-motion support, form `autocomplete` attributes.
- Contact form: confirmation message after submission (FormSubmit `_next` returns to `/contact/?sent=1`), honeypot field. Still posts to FormSubmit.
- Images: new `assets/og-default.jpg` (1200x630, 81 KB, built from the approved hero photo and logo) used for Open Graph and Twitter; `project.webp` reduced from 440,166 to 229,654 bytes (1200x899).
- Open Graph additions: `og:locale en_AU`, image size and alt text, Twitter image alt.
- Sitemap: generated by `scripts/build_sitemap.py` from each page's canonical URL; `changefreq`/`priority` removed; `lastmod` is written only from Git history when available (none was available here, so none is written).
- Tooling: `scripts/sync_layout.py` keeps header, footer, head and scripts identical across pages (copied from `partials/`); `seo_audit.py` now audits every page and supports `--strict`; `seo_optimizer.py` no longer hard-codes homepage copy and keeps social tags in sync per page; the review workflow now stages all HTML files; new `strativa-site-checks.yml` runs the checks on every push and pull request.

## Maintaining the site

1. Edit page HTML directly. To change the nav or footer, edit `partials/` and run `python3 scripts/sync_layout.py`.
2. After adding or removing a page run `python3 scripts/build_sitemap.py`, then `python3 scripts/seo_audit.py --strict`.
3. New pages need these markers: `layout:head`, `layout:header`, `layout:footer`, `layout:scripts` (copy any existing page).
